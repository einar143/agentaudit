# AA001: MCP server launched from an unpinned package

**Severity:** high · **Family:** supply chain

## What it detects

An MCP server whose command is a package runner (`npx`, `bunx`, `pnpm dlx`,
`yarn dlx`, `uvx`, `pipx run`, `uv tool run`) and whose package has no exact
version: no version at all, a tag such as `@latest`, or a range.

```json
{ "command": "npx", "args": ["-y", "some-mcp-server"] }
```

## Why it matters

The runner downloads and executes whatever the registry serves at start-up,
with the user's privileges. If the package is compromised or its name is taken
over, the next launch runs the attacker's code. No review step sits between
publish and execution.

## Fix

Pin an exact version: `some-mcp-server@1.4.2` for npm runners,
`some-mcp-server==1.4.2` for Python runners. Update deliberately.

## Known limits

- A pinned version is not an integrity check. It narrows the window; it does
  not verify content.
- Runner flags that take a value other than `-p`, `--package` and `--from` are
  not modelled, so an unusual flag can cause the wrong argument to be read as
  the package.
- Local paths and URLs are skipped here; they belong to other rules.
- A `cmd /c` wrapper is unwrapped. Other shell wrappers (`sh -c "npx ..."`)
  are not yet.
